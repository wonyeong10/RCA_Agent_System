hipstershop + TiDB 구조도

원본 Online Boutique 호출 그래프에, 이 데이터셋에만 있는 TiDB / TiKV / PD 계층을 붙인 그림입니다. 선 모양이 근거의 종류를 뜻합니다.

기준: 2025-06-29 (장애 0건) · trace 24시간 전수 · metric · log

강력 후보 · 확정 아님

productcatalog → TiDB

  • 원본 productcatalog는 JSON 파일을 읽고 DB를 쓰지 않습니다. trace에는 DB 호출 기록이 18일 내내 없습니다.
  • 06-29에 TiDB duration_99th가 64.9초로 튄 구간이 두 번 있었습니다 (UTC 10:11–10:25, 14:11–14:33). 이때 Select는 21/s에서 0.24/s로 떨어졌습니다.
  • 같은 구간 응답시간 중앙값: productcatalog 10ms → 28.8s (×2,800), frontend 81ms → 30.9s (×380, productcatalog 대기). 나머지 서비스는 변화가 없었습니다.
  • 한계: 하루 안의 두 구간이고, 구간 안 요청 수는 평소의 1~5%입니다. recommendation도 productcatalog를 부르지만 느려지지 않았습니다.
  • 분당 요청 수 상관은 4일 모두 productcatalog·recommendation·cart·redis-cart가 붙어 있어 근거에서 뺐습니다.
metric 라벨

TiDB → TiKV

  • TiKV grpc_qps의 type이 kv_get, kv_batch_get, kv_prewrite, kv_commit입니다. SQL 계층이 보내는 요청 종류입니다.
  • TiDB failed_query_ops의 type에 tikv:9001, tikv:9005가 있습니다. TiKV에서 올라온 오류 코드입니다.
  • 인스턴스: TiDB 10.233.74.171:10080, TiKV 10.233.85.118:20180, 각 1개.
일반 지식

TiDB · TiKV → PD

  • PD metric에는 pod 이름 tidb-pd-0만 있고 IP가 없어 노드를 알 수 없습니다.
  • PD 호출 관계는 데이터에 드러나지 않습니다. TiDB 구조상 TSO 발급과 region 위치 조회를 PD가 맡습니다.
관측 범위

어디서 보이고 어디서 안 보이나

  • TiDB 계층은 trace·log·infra_pod에 없고 infra metric으로만 보입니다.
  • 배치 노드는 pod IP 3번째 옥텟으로 판단했습니다. trace의 pod IP·노드 쌍에서 옥텟과 노드가 1:1입니다. 날마다 바뀔 수 있습니다.
  • TiDB metric은 trace보다 1분 늦게 찍힙니다. trace의 t분 활동이 TiDB 지표의 t+1분 행에 나타납니다 (구간 끝 시각 라벨로 추정).
